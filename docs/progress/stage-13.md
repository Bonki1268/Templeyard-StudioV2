## 3. 無障礙檢查（對照 04「互動與無障礙」）

| 規則 | 結果 |
| --- | --- |
| 可點的東西都是 `<button>`／`<a>`；圖示按鈕有名稱 | ✔ 沒有在 `div`／`span`／`li`／`img` 上綁點擊；情境測試全部用 `getByRole` 找得到 |
| 點擊目標至少 44px | ✔ 修正 1 處：成品面板縮圖下的「細修：第 N 格」連結（原本約 18px 高） |
| 焦點框 | ✔ `global.css` 的 `:focus-visible`；時間軸邊界另有焦點樣式 |
| 文字對比 4.5:1、色彩不是唯一提示 | ✔ token 有對比測試；狀態都有文字標籤（例如「需重新確認」） |
| 拖曳有鍵盤替代 | ✔ 卡片上下移、時間軸加減秒數（第 7 階段） |
| 動畫尊重 `prefers-reduced-motion` | ✔ 用到動畫的兩個檔案都有減少動態的設定 |
| 生成中、完成以 `role="status"`／`aria-live` 宣告 | ✔ 生成中面板、成品「從第 N 格開始播放」 |
| 錯誤訊息放在欄位下方、說明原因 | ✔ 表單錯誤用 `fieldErrors` 顯示在欄位下；生成錯誤用 `role="alert"` |

沒做的檢查：用螢幕閱讀器實際操作、用自動工具（例如 axe）掃描。這兩項需要新增套件或人工操作，建議實測時一起看。

## 4. 文件與程式不一致的地方（請勾選要改的）

勾選的項目我才會改。「改程式」表示要回到 BDD 流程修改程式；「改文件」表示照實作更新文件。

- [ ] 1. **02 Node 版本**：02 寫 Node.js 20，實際用 Node 24（`.nvmrc`、`engines`）。建議改文件。
- [ ] 2. **05 API 清單**：實作多了不少端點，例如：
  - `GET /api/videos/:id/frames`、`GET /api/videos/:id/clips`
  - `/shots/:shotKey/*`（細修、上傳、選回、限定範圍修改、關鍵畫格、單格對話）
  - `/frames/confirm`、`/final/confirm`
  - `/consents`、`/cost-estimate`
  - 定裝版的視角重生、確認、另存版本

  各階段報告第 3 節都有列。建議在 05 補一張完整的 API 表。
- [ ] 3. **05 資料表**：
  - `shots` 多了 `native_voice`、`candidate_count`（生成設定）。
  - `clips.based_on.revision` 記對話修改的調整指令。
  - `finals` 的「需重新確認」不另存欄位，是推算出來的。

  建議改文件。
- [ ] 4. **02 生成指令節點**：背景音樂沒有生成指令檔，曲風寫在 `workflows` 的 `music.tags`。建議在 02「生成指令組裝」補一句；或改成新增一個節點（改程式，Prompt Studio 的測試也要改）。
- [ ] 5. **02 影片合成的參數**：
  - 實作用的值：x264 `ultrafast`、crf 20；`loudnorm` I=−16；背景音樂音量 0.35；字幕 Noto Sans TC 64px、下方置中。

  建議改文件，把這些值寫進去。
- [ ] 6. **03 影片的階段**：
  - 03 的狀態圖是「成品 → 下載」。
  - 實作是「確認並下載」後階段變成 `done`；影片有一格失敗時回到 `frames`。

  建議改文件。
- [ ] 7. **04 警告色 token**：
  - 04 只有 `--color-warning-surface`，「需重新確認」的警告色框也只能用它。
  - 建議在 04 加一個警告框線的 token（改文件，再改程式用新 token）。
- [ ] 8. **04 細修頁的設定區塊**：04 寫「…生成設定、進階、版本」，實作的區塊名稱是「進階：生成指令」。建議改文件。
