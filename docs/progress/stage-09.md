## 3. 新增的套件與自己取的名稱

沒有新增套件。

文件沒寫、自己取的名稱：

- API：
  - `GET /api/videos/:id/frames`：每格的精緻圖與生成狀態。
  - `POST /api/videos/:id/shots/:shotKey/frames/confirm`：確認這一格。
  - 05 有列、這階段實作的：
    - `POST /api/videos/:id/generate/frames`
    - `POST /api/videos/:id/shots/:shotKey/regenerate`（body 的 `kind` 是 first／last）
    - `GET /api/videos/:id/events`：SSE。這階段只送精緻圖的生成狀態；沒有在生成時送出目前狀態就結束。
- 精緻圖一格的狀態：還沒產生、生成中、生成失敗、待確認、需重新確認、已確認。
- 「確認這一格」寫進 `frames.selected`（05 的「選定圖」）。
- 元件：`FramesPanel`、`GeneratingPanel`、`useFrameNotification`、`notify.ts`。
- 實作決定：
  - 同一批送出的精緻圖算成一批，生成中面板顯示「精緻圖・N 格」，N 是這一批的格數，不逐格顯示進度。
  - 任何精緻圖在生成時（包括單格重生），精緻圖面板都只顯示「生成中」。
  - 參考圖的順序：角色定裝圖 → 定裝版視角圖 → 對應照片的去識別圖，最多到模型的參考圖上限。這要先實測上傳方式（07）；在那之前，正式環境按「生成」會說明「待實測」，不會送出。
  - 通知：按下「生成」時才詢問通知權限（瀏覽器只允許使用者操作時詢問）。完成後通知一次「精緻圖生成完成」；沒有允許就不通知。
  - 畫面用每秒重新讀取掌握生成狀態；`/api/videos/:id/events` 給其他用途（例如之後的通知）使用，畫面目前沒有用它。
  - 失效規則接上了「方案改版」與「角色另存新版本」。「寺廟定裝版有新版本」的規則已實作並測試，但目前定裝版確認後要另存新版本才會換版，這個時間點還沒接上通知。
  - 「還不能生成」的原因先列角色，再列方案的檢查。
  - `planEditor.ts` 的 `generateBlockers` 還在（有第 7 階段的測試），但方案面板已經不用；下一次紅燈時移除。

## 4. 對齊檢查

1. **對應的 feature**：F14、F22。F12 的「需重新確認」標示已經在精緻圖面板。
2. **有沒有做到「這一版不做的東西」**：沒有。只顯示「生成中」，不逐格顯示進度（01 這一版不做）。
3. **名稱是否一致**：
   - 資料表 `frames` 的欄位依 05。
   - 影片階段 `frames_generating`、`frames` 依 05。
   - 05 沒列的端點：見第 3 節。
4. **金鑰或原圖有沒有可能被送出**：
   - 參考圖上傳用 `sendAsset`，型別上只收 `CloudOkAsset`；照片用 `deidentifiedAssetId`。
   - 單元測試與情境都驗證原圖沒有上傳。
5. **付費生成能不能不經同意就觸發**：不能。
   - 生成與單格重生都要先取得同意憑證。
   - 沒有憑證時回 409，不留精緻圖與生成紀錄（有測試）。
   - 方案檢查沒過或角色沒確認時，連同意都不會問，直接說明原因。
