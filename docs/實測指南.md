# 實測指南（Comfy Cloud 探測）

這份說明給你自己跑實測用。Claude Code 不會執行這些指令（CLAUDE.md「不花錢」「不碰金鑰」）。

## 為什麼要先探測

系統裡有三個設定要知道 Comfy Cloud 的真實格式才能填，填好之前，產生精緻圖與影片會在送出前停下來，說明「待實測」：

| 設定（`workflows/models.json`） | 影響 |
| --- | --- |
| `upload`：圖片怎麼上傳 | 所有參考圖（定裝版照片、角色、精緻圖、首格） |
| Nano Banana Pro 的 `references`：參考圖放在哪個參數 | 精緻圖、角色定裝圖 |
| Gemini 的 `frameInputs`：首格、末格放在哪個參數 | 分鏡影片 |

## 事前準備

1. 在 repo 根目錄的 `.env.local` 設好 `COMFY_CLOUD_API_KEY` 與 `COMFY_MCP_URL`（名稱見 `.env.example`）。
2. 第 2 輪會用到一張測試圖，請用已經去識別、沒有可辨識人臉的圖。

## 第 1 輪：不花錢

```
pnpm probe:comfy
```

- 這一輪只做查詢，不會建立任何任務：
  - 呼叫 `tools/list`，列出所有工具與參數格式，包括上傳工具。
  - 查 Gemini 範本的參數格式。
  - 搜尋首尾畫格、Wan 關鍵畫格的範本，以及 Nano Banana Pro 的寫法說明。
- 結果存在 `data/probe/<時間>/`。這個資料夾已列入 `.gitignore`，裡面不會有金鑰。
- **把這個資料夾交給 Claude Code。** 它會依結果寫好第 2 輪的請求檔（上傳一張圖、用 Nano Banana Pro 和 Gemini 各生成一次）。

## 第 2 輪：先預演，再真的送出

```
pnpm probe:comfy -- --requests <請求檔>
```

預演：只做不花錢的呼叫（例如上傳），付費的那幾筆只印出會送什麼，不會送出。

```
pnpm probe:comfy -- --requests <請求檔> --confirm
```

真的送出：付費的每一筆會先顯示雲端回的扣點說明，問你「要送出嗎？」，**輸入 y 才送出**，其他鍵就略過。完成後會記下產出的網址。

跑完後：

1. 到 Comfy Cloud 的帳單頁記下實際扣點。
2. 把這次的 `data/probe/` 資料夾交給 Claude Code。它會：
   - 填好 `workflows/models.json`；
   - 補上對應的測試；
   - 更新 `docs/07-實測紀錄.md`（要你同意才改）。

## 之後：用完成的系統完整走一次（第 13 階段）

設定填好後，就可以用一間真實寺廟與你的照片，從建立影片一路走到下載成品。

開始前，先在系統裡設定這支影片的費用上限與單筆同意門檻。
