# 06 Implementation Plan：先做哪樣

廟埕影室（Templeyard Studio）· 2026-11-02

## 怎麼交給 Claude Code

repo 根目錄的 `CLAUDE.md` 寫了開發規則，`.claude/` 裡有一鍵指令、子代理與保護測試的 hook。

- `/next-stage`：做下一個階段，做完停下來回報。
- `/auto-dev`：從目前階段一路做下去，遇到停止條件才停；`/auto-dev 7` 做完第 7 階段就停。
- 進度記在 `docs/PROGRESS.md`，每個階段的報告在 `docs/progress/`。

每個階段都用 BDD＋TDD：情境 → 紅燈（先 commit 測試）→ 綠燈（再 commit 實作）→ 重構 → 收尾，最後由沒參與實作的稽核子代理檢查。完成條件是下面各階段列出的條件，加上「綠燈之後沒有改過測試」。

## 第 0 階段：實測與專案骨架

**目的**：先確認會影響設計的未知數，再搭好專案。

- 實測（每項只用一格分鏡；已完成的見 `docs/07-實測紀錄.md`）：
  - 已完成：Comfy Cloud MCP 的連線、送出、雲端確認、輪詢、下載、重啟恢復；Gemini Omni 文字生成影片；Seedance 2.0 Mini；Nano Banana 2 Lite；ACE-Step。
  - 待測：`tools/list`（圖片怎麼交給 MCP）、Gemini 圖片輸入（首格＋末格＋參考圖）與 1080p、Nano Banana Pro、中文對口型與語速、去背景音樂、Wan 2.2 多關鍵畫格、實際扣點。
  - 結果補進 07，必要時回頭修改 01～05。
- 專案骨架：pnpm monorepo（`apps/web`、`apps/server`、`packages/*`）、TypeScript 設定、ESLint、Vitest、Playwright、`.env.example`。
- 把既有的 `prompt-studio/` 與 `prompts/` 搬進 repo，確認原本 8 項測試仍通過。

**完成條件**：`pnpm dev` 能同時啟動前後端並顯示空白首頁；`pnpm test`、`pnpm typecheck`、`pnpm lint` 全部通過；實測紀錄已寫入。

## 第 1 階段：寺廟資料庫

- 匯入腳本：讀 `data/temples.csv`，依 05 Backend Schema 的清理規則寫入 `temples`。
- 紀年換算：民國、民前、清代年號、日據紀年轉西元；無法判斷留空；保留原始值。查證萬壽宮、慈德廟的換算。
- 搜尋 API：模糊比對（臺／台、財團法人前綴）、行政區、主祀神明；預設排除已廢止與未登記。

**完成條件**：匯入後有效寺廟 940 間；紀年換算的單元測試涵蓋每種紀年；搜尋測試涵蓋模糊比對與排除規則。

## 第 2 階段：系列專案與首頁

- `series` 資料表與 API。
- 首頁：系列卡片列表、建立系列表單（依 04 Design Brief 的元件與 token）。
- 設計 token 與共用元件：按鈕、選項按鈕、輸入框、標籤、底部操作列、AI 幫我寫按鈕（先不接 AI）。

**完成條件**：Playwright 測試能建立系列並在列表看到；元件的無障礙檢查（焦點、標籤、對比）通過。

## 第 3 階段：建立影片、照片上傳與去識別

- 建立影片頁：步驟列、選寺廟、選模型（顯示模型能力表）。
- 照片上傳：瀏覽器端 MediaPipe 人臉偵測、遮蔽框編輯（新增、刪除、取消）、手動車牌遮蔽。
- 後端：原圖與去識別圖分開存；`assets.cloud_ok` 規則。
- 視角對照：先以手動指定視角；自動判讀可在第 5 階段以 Claude 讀圖補上。

**完成條件**：測試證明原圖資產 `cloud_ok = 0`，且任何送雲端的函式在型別與執行期都拒絕它；遮蔽框可新增、取消。

## 第 4 階段：轉接層、指令組裝、費用控制

- `packages/comfy-client`：MCP 初始化與 session 過期重連、`partner_generate`／`run_template`、雲端確認（`confirm: true`）、`get_job_status` 輪詢、`get_output` 下載、圖片輸入、錯誤處理、同時執行數佇列、任務中斷恢復。改寫自 `comfyui-test/server.mjs`，加上型別與測試。
- `workflows/`：各模型的呼叫設定（工具、模型代號或範本名稱、節點覆寫）。
- `packages/prompts`：讀 prompt JSON、套用模型寫法、插入連續性鎖、單格自訂指令優先、寫入呼叫綁定。
- Prompt Studio 擴充：呼叫綁定欄位與驗證、新節點、16:9。
- 費用：預估、預留、結算、上限與單筆門檻、同意憑證；本系統同意後才帶 `confirm: true`。

**完成條件**：假 MCP 伺服器測試涵蓋成功、失敗、逾時、session 過期、雲端要求確認、重啟後取回；指令組裝的快照測試；費用超過上限時 API 回傳「需要同意」。

## 第 5 階段：寺廟定裝版

- 產生定裝版：依視角清單生成空景視角圖；模型在此鎖定。
- 定裝版頁：單張重生、修改（含 AI 幫我寫）、AI 推測標示、確認。
- 沿用：同系列同一間廟直接沿用；另存新版本。
- 依 drama-skills 的地點與視角、場景空鏡寫法撰寫 `temple-view` 指令。

**完成條件**：模型鎖定後 API 拒絕更改模型；AI 推測的視角未確認時不能進入創作工作區；沿用流程的端到端測試。

## 第 6 階段：創作 Agent、對話、問卷、AI 輔助撰寫

- `packages/agent`：Claude 工具定義（查詢寺廟、讀取系列、產生問卷、預估費用等），付費工具需同意憑證。
- 創作工作區版面：左對話（SSE 串流）、右面板切換。
- 創作首頁、問卷面板（選項＋或自己寫、留白由系統選、答案來源標籤）、系列問卷預設值。
- AI 輔助撰寫：通用的「AI 幫我寫」元件與 `/api/assist`，先接上第 1～4 步的欄位。

**完成條件**：以錄製回應測試 Agent 工具流程；第一支影片送出問卷後系列預設值被寫入、第二支影片自動帶入；AI 建議只有按「採用」才會填入。

## 第 7 階段：分鏡方案、時間軸、秒數檢查

- Agent 產生方案（工具 schema＋Zod 驗證＋一次自動修正）；依 drama-skills 的分鏡寫法。
- 方案面板：風格、角色、場景三張卡；分鏡卡片編輯、拖曳排序（含鍵盤替代）；時間軸邊界拖曳。
- 方案版本：每次修改新增版本、版本選單、回到舊版。
- 秒數檢查：總長、最短生成長度、對白估時（暫定每秒約 4 字，實測後更新）。
- 對話修改方案：Agent 回覆列出改了哪幾格。

**完成條件**：秒數檢查與對白估時的單元測試；`shot_key` 跨版本不變的測試；檢查未通過時「生成」不可按且列出原因。

## 第 8 階段：角色定裝版、補充視角

- 新角色：描述、連續性鎖（AI 幫我寫）、產生三視圖與定裝圖、確認；設為系列角色。
- 補充視角：卡片標示缺少視角，補產生並確認。

**完成條件**：角色未確認或缺少視角時不能生成；連續性鎖確實出現在後續指令中（指令組裝測試）。

## 第 9 階段：精緻圖、生成中、通知

- 生成精緻圖（首格；需要時末格與關鍵畫格），參考角色定裝圖、定裝版視角圖與照片。
- 生成中面板：只顯示「生成中」與內容類型；可離開；瀏覽器通知。
- 精緻圖面板：單格重生、需重新確認標示、生成影片按鈕的條件。
- 確認失效規則的實作（03 App Flow 的對照表）。

**完成條件**：重新整理或重啟後仍顯示生成中並能取回結果；失效規則的單元測試涵蓋每一列。

## 第 10 階段：分鏡細修與中間關鍵畫格

- 細修頁三欄版面、縮圖列切換、單格時間軸。
- 設定面板：內容、鏡頭、參考素材（含上傳自己的首格／末格並去識別）、畫格、生成設定、進階生成指令、版本。
- 中間關鍵畫格：時間點規則、建議時間點、產生、使用提醒。
- 限定範圍修改：圈選區域＋指令。
- 只針對這一格的對話。

**完成條件**：時間點規則的單元測試（範圍、間隔 ≥ 1 秒、最多 4 張）；自訂指令不被節點指令更新覆蓋的測試；細修後該格標示需重新確認。

## 第 11 階段：影片生成與合成

- 依影片模型生成每格影片；軟性控制（Gemini、Seedance）與精準控制（Wan）兩種寫法；依 drama-skills 的影片指令寫法。
- 偏差比對：擷取指定時間點畫面，計算與關鍵畫格的相似度並顯示。
- FFmpeg 合成：裁切、720p 片段放大到 1080p、串接、字幕 ASS 燒錄、背景音樂（ACE-Step）、響度統一、輸出規格。

**完成條件**：以測試素材跑合成，輸出 1920×1080、24 fps、長度與卡片秒數總和一致；字幕文字與卡片字幕欄一致。

## 第 12 階段：成品、複製影片、下載

- 成品面板：播放器、各格縮圖條、模型與規格資訊。
- 對話修改成品：判斷重生哪幾格、顯示費用、確認後重生並重新合成。
- 複製影片：帶入寺廟、問卷、方案，前往建立影片頁改選模型。
- 下載。

**完成條件**：複製後新影片不含已生成的圖與影片；端到端測試從成品修改一格並重新合成。

## 第 13 階段：整體驗收

- 用一間真實寺廟、自己的照片完整走一次（實測，花費先估算並同意）。
- 對照 01 PRD 的功能清單逐項確認；對照 04 Design Brief 做無障礙檢查。
- 更新規格書與這 6 份文件中與實作不同的地方。

**完成條件**：功能清單 F1～F22 全部打勾；成品符合影片規格；文件與程式一致。

## 第 14 階段：系列頁（設定、角色庫、過去的影片）

依設計稿 `docs/design/series/` 與 03「系列頁」。第 13 階段已做的部分（修改系列、角色庫的新增／修改／產生定裝圖／確認、AI 幫我寫、影片列表）沿用並改成分頁版面；這個階段補齊：

- **版面與路由**：頂端系列名稱與數量；「系列設定」「角色庫」「過去的影片」三個分頁各有路由，可直接開啟、互相切換；角色詳情為獨立路由。
- **系列設定分頁**：
  - 問卷預設值逐題修改或清除，標明來源影片；「想講的故事」等每支影片不同的題目不列入；長度在問卷預設值裡。
  - 影片模型卡片（特性、參考單價）；選 Wan 2.2 而問卷預設需要角色說話時顯示對口型提醒。
  - 費用區塊讀寫全域設定（新影片的費用上限、單筆同意門檻）。
  - 底部操作列列出未儲存的變更；有未儲存變更時離開先提醒。
  - 影片建立時保存 `series_snapshot`，之後生成讀這份設定（「修改只影響之後新增的影片」）；既有影片以建立當下可取得的系列設定補上一份。
- **角色庫分頁**：搜尋、篩選（全部／系列角色／影片專屬）；列出這個系列影片的影片專屬角色，可「設為系列角色」；角色卡顯示用在幾支影片與目前版本。
- **角色詳情**：版本切換（三視圖、定裝圖、確認日期、差別說明）；身份錨點與造型分開編輯（`character-design` 節點已輸出這兩欄）；連續性鎖逐條編輯；分別重生三視圖或定裝圖（費用同意）；用到這個角色的影片與版本；已確認的角色另存新版本。
- **過去的影片分頁**：篩選（全部／製作中／完成）與排序；影片卡的狀態細節、鎖定模型、成品長度、「問卷預設來源」標籤；繼續製作／開啟成品、複製這支影片、下載（只限完成）。

**完成條件**：
- 三個分頁與角色詳情都能直接以網址開啟、互相切換。
- 修改問卷預設值後，下一支新影片帶入新值；已建立影片的問卷不變。
- 修改系列視覺風格後，既有影片組出的生成指令仍是建立時保存的風格（指令組裝測試）。
- 影片篩選、排序與狀態細節文字的單元測試；角色庫篩選與搜尋的單元測試。
- 設為系列角色後出現在「系列角色」篩選，並可在同系列新影片沿用。
- 角色詳情切換版本時三視圖、定裝圖與「用到的影片」對應正確版本；重生沒有同意憑證時 API 回 409。
- 分頁、篩選按鈕、版本切換的無障礙檢查（`aria-current`、`aria-pressed`、焦點框）。

第 14 階段可以在第 13 階段的實測完成前先做；做完後第 13 階段的「F1～F22 全部打勾、文件與程式一致」要再對一次。
