# Location / View 設計

## 分工

- **Location** 儲存空間身份：可行走的地理、分割槽關係、入口、固定錨點和主要材料。
- **View** 儲存可複用的觀看方向/生產狀態：面向哪個區域、哪些錨點同時可見，以及
  陳設階段、時段、天氣、光態。

Location/View 分別記錄空間身份和可複用檢視，讓參考圖、分鏡和相鄰鏡頭共享同一空間邏輯。
當前都寫在 `視覺設定.md` 的地點條目中，單鏡機位由分鏡決定。

## 先明確空間關係，再寫氛圍

讀取劇本時先整理：

1. 內/外與可通行邊界；
2. 區域之間的相對關係；
3. 人和道具會使用的入口/出口；
4. 不能移動的識別錨點；
5. 主要材料、尺度和功能；
6. 劇本明確的時間、天氣與有因果的光源。

“潮溼、壓迫、懷舊”可以輔助氣氛，卻不能替代“北門通走廊、視窗面向河面、配電箱
在櫃檯後”這樣的地理事實。也不能為了畫面好看新增一扇後來影響追逐路線的門。

地點裡的方位用錨點互相定位（“窗在書櫃牆靠門的一端”“門正對辦公桌”），或用場景自己的
方向（北門、東窗），不寫裸的“左側大窗”“門在左後角”：不說站在哪裡看，左右就會在反打
鏡頭裡對調，下游只能猜。只有 View 已經寫明從哪裡朝哪裡看時，才在 View 裡用畫面左右。

## Location 邊界

### 新 Location

當空間具有不同、可獨立生產的地理/入口/固定錨點時新建。例如同一渡站建築裡的候船
廳和值班室各自有完整動作和明確連線，適合兩個 Location，並在地點條目中說明連線關係。

### 同一 Location

停電前後、白天夜晚、晴雨、臨時佈置變化都不改變空間身份。若只因鏡頭轉向就新建
地點，會讓門窗方向和演員動線互相矛盾。

**`reviewed_invariant` AST-04**： 固定地理與臨時時段/天氣/燈光不得混成兩個
Location identity。

## View 邊界

View 值得存在，是因為下游要反覆引用一種穩定、能說明空間的方向或狀態：

- 從櫃檯側朝北門，能同時看到門、河窗和配電箱；
- 停電後的同方向，主燈滅、只剩河窗冷光；
- 暴雨期外景，站牌、臺階和河岸關係保持，天氣和地面狀態變化。

單純“低機位”“特寫門把手”“35mm”屬於 shot/keyframe，不建 View。演員站在左邊也
不是地點事實。**`craft_default` AST-03**： 一組鏡頭能共用方向/狀態並需要參考 plate
時才在地點條目中記錄獨立 View。

## 光、天氣和陳設必須有來源

- 劇本寫停電，則 View 可從 `normal_night` 變為 `blackout`，cause 指向斷電 block；
- 創作者選擇藍調夜景是 visual direction，可記錄 creator source；
- 不能因 prompt 慣性擅加霓虹、霧、逆光或移動窗戶；
- 臨時海報、散落檔案、積水若會影響故事/連續性，進入 View state 或 delta；普通可替換
  裝飾可留作 set dressing。

## 合成例：舊渡站值班室

`LOC-FERRY-OFFICE`：狹長室內；北門通候船廳；東側河窗；西側整面舊櫃檯；配電箱
固定在櫃檯後牆。Location 不寫“夜”“暴雨”“顧禾站在門口”。

- `VIEW-FERRY-OFFICE-NORTH-NIGHT`：從櫃檯內側朝北門，河窗位於畫面右後方；夜間
  頂燈正常，櫃檯上只有鐵皮匣。
- `VIEW-FERRY-OFFICE-NORTH-BLACKOUT`：同一地理和方向；斷電後頂燈滅，河窗冷光
  保留，鐵皮匣位置不變。它是 View/state 變體，不是“黑暗值班室”新 Location。

如果劇本只需要一次門把手特寫，無需 `VIEW-FERRY-OFFICE-DOOR-CLOSEUP`；鏡頭可以
引用 Location/既有 View 後自行擁有 framing。

## 檢查問題

- 不看氛圍詞，仍能判斷入口、固定錨點和區域關係嗎？
- 同一空間各 View 的門窗/光向是否保持可調和？
- View 是否錯誤擁有相機焦段、演員站位或 shot boundary？
- 時段、天氣、光態與陳設變化有 source/cause/validity 嗎？
- 相鄰空間該拆 Location 還是做 View，是否依據地理和製作複用，而非名稱習慣？
- creator 是否明確選擇空景/含角色政策？該政策由後續 image prompt 具體實現。

空間拆分顆粒度屬於 **`taste_option`**；無論選粗或細，入口關係與連續性都要有一致依據。
