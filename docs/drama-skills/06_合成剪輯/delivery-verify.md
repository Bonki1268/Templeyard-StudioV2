# 交付與驗收

檢查實際交付檔案，並區分實測結果、人工判斷和未測項。

| 項 | 怎麼核對 |
|---|---|
| 時長與切點 | 對照實際渲染區間、幀邊界和使用者時長要求 |
| 內容覆蓋 | 對照分鏡和影片提示詞，必要內容有承載，未採用鏡頭有原因 |
| 台詞 | 在成片上回聽，必要時轉寫輔助，逐句對照劇本 |
| 邊界幀 | 檢視剪輯點前後，檢查意外黑白幀、畫面斷裂和漂移；逐幀檢視 `verify` 列出的疑似壞幀 |
| 聲音 | 回聽接縫、對白清晰度與已宣告靜默；測量整片響度 |
| 字幕 | 檢查逐字內容、發聲時間、字號、折行和畫內文字避讓 |
| 畫內文字 | 按劇本與視覺設定的文字政策檢查載體、可讀性和指定文字 |
| 畫幅與幀率 | 探測輸出檔案，對照交付規格 |
| 接鏡色彩 | 在同場景、同光態下比較可比區域，確認校正沒有過沖；先看 `verify` 點名的切點 |

`verify` 只提供部分技術測量，不能替代回聽與畫面檢查。
分段色彩觀測按當前剪輯單讀取中間分段，報告平均亮度和藍減紅畫素值；它不代表成片區域性區域的
接鏡殘差，也不要求各場景接近同一均值。改動剪輯單後先重新渲染，再測量並檢視實際切點。
發現有意黑場、靜默或光態變化時按創作意圖判斷，不因數值異常直接判錯。

`verify` 還逐幀讀成片：「切點亮度變化」是每個切點前後兩幀的平均亮度差（0–255），超過 20 的
列進「請逐幀檢視」；「疑似壞幀」是與前後兩幀都明顯不同、而前後兩幀彼此相近的單幀，常見於解碼
錯位，畫面文字入場的一兩幀故障效果也會被列出並標明。兩項都只指出該看哪裡，不阻斷交付。

## 交付

給出成片、剪輯單、可繼續編輯的中間檔案，以及外部混音或字幕工程（如使用）。
說明是否滿足使用者要求、仍有哪些內容缺口和取捨；測不了的必要專案寫明原因。

需要補素材、改台詞或改分鏡時，指出對應鏡頭與發生時間並交給負責階段。
渲染成功只證明工具完成執行，成片的內容判斷需要觀看和回聽；正式審查由
`$short-drama-review` 或創作者進行。
