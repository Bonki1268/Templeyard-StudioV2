來自對角色、場景、物品資產如何進入後續鏡頭的定性案例閱讀，示例均為合成改寫。
通用方法見 [common-recipe.md](common-recipe.md)；本文件提供可按專案調整的生產版式。
核心原則：**先明確資產負責的穩定身份與當前版本，再讓分鏡負責本鏡呈現**。純白底、
無情緒、三檢視只是便於識別的一種專案選擇；帶環境的背景、單檢視或帶狀態的參考板
只要更符合複用目的且不混淆身份與臨時狀態，也可以由創作者選擇（IMG-03/IMG-04）。

## 一、角色參考板

先寫 `reuse_job`：下游需要保持身份識別、當前造型、某種狀態，還是某個可操作部位？然後
選擇最少但足夠比較的檢視、背景和光線。頭肩、全身、側背、單檢視、上下文參考或中性
板式都可以；背景和檢視數量不是角色身份的一部分。

以下是可選記錄方式；與 `reuse_job` 無關的行可以省略：

```text
用途：<這張板要讓下游保持什麼>。
身份識別特徵：<少量穩定、可見、彼此不重複的臉型/髮型/體態/識別標記>。
當前造型或狀態：<只寫已接受版本的可見變化和有效範圍>。
版式：<為複用職責選擇的檢視、佔畫關係、背景與比較方式；多檢視並排時寫明畫面內不出現檢視標籤、引線箭頭、尺寸標註與圖注>。
光線與文字：<幫助識別材質/結構的光線；已接受的文字方案與顯示位置>。
排除：<當前最可能越權匯入或漂移的事實>。
```

若專案已驗證特殊分隔、權重或引子，可在最後交付時採用；通用資產說明不儲存這些
供應商寫法，也不把解析度、品質詞或固定收尾當成資產品質。

### 決策規則

- **布光服務識別職責**：先問哪些臉部結構、材質、輪廓或狀態必須可比較，再選擇光源
  方向、面積和反差。光型不自動編碼性別、階級、善惡或權力；同一造型的識別錨點與
  參考圖用途必須保持穩定。
- **社會處境要有已接受依據**：磨損、整潔、改制、借用、制服紀律或刻意偽裝都可能
  承載人物處境，但不能從貧富、性別、年齡或題材標籤自動推出服裝和布光。先引用角色
  行動、職業條件、當前選擇或已接受設定，再決定哪些可見細節值得複用。
- **視覺細節要有職責**（IMG-02 的強化）：它應服務身份識別、當前狀態、結構功能或
  下游複用。寫不出職責或與其他錨點競爭的裝飾優先刪除。
- **狀態是否需要新版本按複用判斷**：被俘或重傷等狀態若跨鏡複用、影響識別或連續性，
  由資產負責技能確認新的造型或狀態版本；只在一鏡發生且已完整寫入鏡頭邊界時不必擴張資產表。
- **風格標籤按專案新增**：按專案風格前置 `【真人風格，寫實風格】` /
  `【國漫風，二次元畫風】` 等，設計稿本體不帶標籤。

### 布光詞彙：按“要比較什麼”選，不按身份標籤對映

先確定這張板必須讓下游比較什麼——骨骼體積、表面材質、外輪廓與體量、服裝層次，還是狀態
痕跡——再從下列詞彙裡選。每種光型的條目只說明它讓什麼結構變得可比較、又壓掉什麼。

| 光型 | 讓什麼可比較 | 壓掉什麼 |
|---|---|---|
| 均勻正面光（平光） | 五官相對位置、妝面、服色與圖案 | 顴骨、鼻樑、下頜等體積起伏 |
| 側光 / 高位斜側光 | 明暗交界線兩側的骨骼體積與輪廓起伏 | 暗側細節；同時放大不對稱 |
| 頂光 | 眼窩、鼻下、頜下的縱向結構關係 | 暗區中的識別細節與服裝層次 |
| 底光 | （反轉日常明暗方向）非常規體積讀法 | 常規結構讀法，做識別板時不可用 |
| 大面積柔光 | 材質紋理、膚質、布料表面狀態 | 形狀邊界與輪廓銳度 |
| 小面積硬光 | 反射差異、磨損、鏡面高光與工藝痕跡 | 過渡資訊；放大瑕疵與形變 |
| 輪廓光 / 逆光邊緣光 | 外輪廓、髮型剪影、服裝廓形與前後分離 | 面部識別資訊，不單獨承擔身份板 |
| 場景內實際光源 | 狀態板與環境內參考板的光向可核對性 | 中性比較條件，需與場景已接受光向一致 |

以上光型按“本板必須讓人比較什麼”選擇，**不按性別、年齡、貧富或題材標籤
對映**。同一光型可用於任何角色；專案裡若出現“女性一律柔光、男性一律側光”這類預設，那是
未經證據的模板化，先刪除再按 `reuse_job` 重選。社會處境仍按上一條規則從已接受依據取證。

繪製形態裡“光”由上色關係與陰影形狀承擔，這張表的選擇依據不變——變的只是它落到哪一層的
陰影形狀與邊緣處理，由已接受的製作形態決定。

### 合成判斷例：同一角色的偽裝期

- `identity`：窄長臉、左眉舊缺口、略前傾但穩定的走路重心；這些跨造型保持。
- `look_state`：本段穿借來的制服，袖長不合身，胸牌按上游要求設為 `graphic-only`；
  這些只在偽裝有效範圍內保持。
- `reuse_job`：近景靠眉缺口識別，全身排程靠重心和制服輪廓識別。
- `layout`：選擇一個能看清面部錨點的檢視和一個能比較制服輪廓的檢視；背景只需不
  干擾識別，不要求白底或固定佔比。兩檢視並排等高，寫「畫面內無檢視標籤、無引線箭頭、
  無尺寸標註、無圖注」。
- `exclusion`：不從“偽裝者”標籤追加陰影臉、可疑眼神或無來源武器。

## 二、場景方位板

只有攝影方向會改變入口、可見地理、光源、遮擋或敘事功能時才建立觀察視角。方向可以用
羅盤、門內/外、主桌側/證人側等專案語彙；不為“完整”做齊所有方向。

以下是可選記錄方式；只寫當前觀察面需要核對的內容：

```text
觀察視角：<攝影機在哪一側、朝向哪裡、為何需要這個觀察面>。
固定地理：<入口、路徑、區域、遮擋、可操作部位及其相對關係>。
本版本：<有依據的時間、光線、損壞、佔用或天氣狀態>。
可見邊界：<此觀察視角能看到和看不到什麼；哪些事實暫緩揭示>。
文字/人物政策：<空場、允許的人物類別、標牌與已接受的文字方案>。
```

- 清點順序以當前空間最容易混淆的關係為起點，不要求中心、地面、四向和頭頂全部出現。
- 光源只寫其固定來源和當前版本；反打能否咬合靠相同地理與光向核對，不靠“背後
  來光”公式。
- 觀察視角不自動攜帶情緒。時間、光線和戲劇狀態若變化，明確它屬於場景的固定事實、
  觀察面的可見差異還是本場版本，避免為每個方向發明一套氣氛真相。

## 三、道具參考板

道具板優先讓輪廓、可操作部位、尺度關係、當前狀態和文字政策可比較。白底產品照只是一種
適合孤立結構的版式；道具依賴佩戴、安裝或環境尺度時，可選擇有控制的上下文背景。

以下是可選記錄方式；欄位由道具功能和複用風險決定：

```text
用途與歸屬：<誰如何識別、握持、佩戴、安裝、轉交或損壞它>。
穩定形制：<輪廓、材質、結構、可操作部位及可比較尺度>。
當前狀態：<有依據的磨損、開啟、缺失、汙染或修復>。
版式與光線：<讓上述職責可讀的檢視、背景和材質照明>。
文字：<`exact-readable` / `graphic-only` / `no-readable-text` 及受控顯示位置>。
```

顏色、材質和工藝只是常見識別重點；對鑰匙可能是齒形，對藥瓶可能是封口與文字政策，
對可穿戴物則可能是佩戴關係。欄位由功能和複用風險決定（IMG-05）。

## 四、首幀合成與定點修改指令

下面說明資產參考交給分鏡後的使用邊界；關鍵幀正文仍由分鏡負責技能擁有。每張參考先宣告用途 `role`
和可以參考的內容，限制它能控制的身份、構圖、狀態或文字，避免整張圖覆蓋本鏡事實：

```text
參考 A：`role=identity`；`may_control=<臉型/識別標記>`；`must_not_control=<姿勢/背景/文字>`。
參考 B：`role=geography`；`may_control=<入口/路徑/固定錨點>`；`must_not_control=<臨時人物/故事狀態>`。
本鏡：從已接受起點寫出人物相對站位、朝向、遮擋與可見狀態；構圖和景別服從本鏡目的
與觀眾應看到的資訊；文字服從上游的逐字保留要求。
```

只寫當前執行需要的站位、朝向、尺度和文字風險。若創作者提供的專案觀察證明某類
漂移反覆發生，針對該風險補區域性約束；不把“人物過大/字幕”預設為所有鏡頭缺陷。

區域性修改要同時寫清**修改項與保持項**（IMG-06 的實際寫法）。可以分句解釋複雜區域，
但每項變化都要能指向精確 `IMG-...`、物件和區域，未受影響的事實明確保持：

```text
畫面中右側的甲去掉，畫面中不要出現甲，其他角色站位動作保持不變，其他內容保持不變。
```

多張參考圖即使使用位置編號，也要逐條寫清用途 `role`、`may_control`、`must_not_control` 與檢查
結論；“五官參考若干圖、其他全照圖一”這類讓整圖順帶決定多類內容的指令，應先拆成
可審查的參考繫結。

## 五、資產範圍決策（`craft_default`）

| 決策 | 判斷方式 |
|---|---|
| 是否建角色資產 | 後續需要重複識別、繫結造型、配音或保持連續時才建立。 |
| 是否拆地點與觀察視角 | 攝影方向會改變可見地理、入口、光源或敘事功能時拆分。 |
| 是否建物品資產 | 物品會被識別、持有、轉手、損壞、讀字或承擔回扣時建立。 |
| 描述寫多長 | 寫到能穩定識別與執行即可；刪除不能歸因身份、結構、狀態或用途的裝飾。 |
| 一次覆蓋多少集 | 先抽取完整已接受範圍，再按創作者停靠點接受；不從固定資產數量倒推劇情。 |

## 六、品質判據與反模式

判據：每個細節是否服務身份、當前版本、功能、地理或下游複用；背景、光線和檢視是否
適合 `reuse_job`；角色、道具和場景的參考許可權有沒有互相越界；場景 `View` 是否能核對
入口、路徑與光向；文字政策、角色名和資產繫結是否一致。帶環境的背景或狀態光線不是
天然失敗，但必須明確屬於哪一層，並避免汙染穩定身份。

常見返工原因：

1. 聲稱做中性身份板，卻讓一次性場景光、動作或背景成為身份識別特徵；反之，專案選擇
   上下文狀態板卻被機械清空，丟失其複用職責。
2. 表單欄位直貼描述（"身份:女配\n年齡身高:20歲"）。
3. 描述沒有提供足以識別、操作或核對狀態的事實，不論文字長短。
4. 無語義命名（資產名叫 '1'、'站位'、'參考'——下游無法按名索引）。
5. 收到生產反饋後不診斷身份、構圖、文字或狀態風險，只重複同一描述。
6. 描述內角色名與資產登記名不一致（寫 A 名生成 B 人）。
