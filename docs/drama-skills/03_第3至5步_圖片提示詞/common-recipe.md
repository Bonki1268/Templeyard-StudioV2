## 1. 目的與輸入

資產提示詞把已接受資產中需要保持的事實，寫成便於識別、比較和後續複用的參考圖要求。

開始前取得：`視覺設定.md` 中準確的條目和當前變體、來源場景、用途、目標構圖、視覺風格、
背景與光線、文字政策、創作者引用 `REF-*`、約束與排除項。身份尚未確定時停在提案，
不要用提示詞文案掩蓋缺口。

## 2. 從資產事實到畫面語言

按下列四類選擇當前圖需要的事實：

| 類別 | 問題 | 寫法 |
|---|---|---|
| 識別錨點 | 去掉服裝/天氣後，憑什麼認出它？ | 可見形狀、比例、相對位置、材質特徵 |
| 狀態差異 | 這次與基準版本具體差在哪？ | 有邊界、能直接看到的變化 |
| 複用幾何 | 後續鏡頭最怕哪裡漂移？ | 方位、尺度、入口、握持面、結構關係 |
| 呈現條件 | 怎樣最利於讀清以上事實？ | 構圖、視角、背景、光線、空場政策 |

抽象標籤需要翻譯成證據。例如“冷峻”本身不夠；可在人物表情、站姿、服裝線條或冷色環境中選擇與資產事實相符的可見載體，但不得臆造傷疤、身份或劇情。

### 錨點選擇啟發

- **`craft_default`**：選少量、作用不重複的錨點。輪廓、比例、一個區域性特徵和一個材質或
  色彩關係，通常比十個近義形容詞更穩。
- **`reviewed_invariant`**：錨點必須足以讓審查者區分該身份及所選版本；
  “漂亮、奢華、高畫質”不能代替識別證據。
- **`craft_default`**：用相對關係表達空間，如“服務檯在主入口右前方，後牆有唯一金屬門”，比雜湊物件清單更可複用。
- **`taste_option`**：錨點可以用簡潔技術文風或富有氣氛的中文表達，只要不改變事實優先順序。

## 3. 八段式配方

順序是資訊保真策略，不是必須出現八段標題的僵硬格式。省略不適用段，不省略型別必需事實。

1. **用途與主體**：先說是人物設定圖、場景空鏡、道具參考還是區域性修改，以及主體是誰。
2. **穩定錨點**：身份、地理或形制的持久事實；寫可見和可比較的內容。
3. **版本差異**：只寫這次造型、視角或狀態相對基準版本的差異，以及當前狀態。
4. **構圖與尺度**：視角、畫幅用途、主體佔比、方向、相對位置、比例參照。
5. **材質、色彩與光線**：說明對識別有用的表面、主次色關係、光向和亮暗邏輯。
6. **背景/舞臺政策**：乾淨背景、環境內展示或 `empty_stage`；說明是否允許人群、手或支架。
7. **文字與功能**：引用資產來源中的文字政策，再明確選擇
   `readable | symbolic | blank | postproduction` 這四種呈現方法之一，並說明功能件怎樣可見。
8. **排除與保留**：只寫當前最可能出現的誤讀；區域性修改要先說明必須保留什麼。

### 可複製文體

把內部欄位寫成 `#/format/prompt_language` 宣告語言中的自然表述。避免輸出 JSON 鍵名、`hash`、審查指令、重試歷史、
“請模型務必”、權重語法或某家模型專用的控制詞。ID 與來源放在 Markdown 元資訊裡，
不要塞進正文。正文可以分句，但離開內部資料後仍應讀得懂。

### 通用骨架

```text
[參考圖型別與用途]，[主體與穩定身份/地理/形制錨點]；當前為[該版本的可見差異]。
採用[構圖/視角/方向/尺度與空間關係]；[材質、色彩、光向和氣氛]；[背景或空場政策]。
文字政策：[政策與精確要求]。保持[必要事實]；排除[與必需事實不衝突的高風險誤讀]。
```

這只是填寫順序，不是固定答案。刪掉空項和機械標籤，使成品像視覺部門能直接使用的工作說明。

### 按產物型別裁剪規格

- `character_sheet`：身份錨點繫結一個造型版本，選擇便於識別的構圖；沒有文字承載面時刪除文字欄位。
- `location_plate`：寫清地理、方向和空場政策；標牌文字必須先有已接受的資產政策。
- `prop_plate`：同時交代輪廓、功能、尺度和適用的文書處理。
- `look_state_variant`：繫結基礎來源、可見變化和有效範圍；姿勢本身不自動成為新版本。
- `edit_delta`：只保留精確目標、變化、保持項和連續性影響；上游負責的變化先取得其接受。

參考說明不是普通圖片清單。每張只宣告一個主要用途，分別寫清可借用和不可帶入的事實；沒有參考
媒體時，條目仍寫 `- 參考：無外部參考`。
有參考卻沒有觀察證據時保持“未驗證”並列出風險。

## 4. 錨點、約束與取捨

### 身份

身份錨點必須在臨時狀態改變後仍然成立。服裝、淋溼、汙漬、手持物和當下表情通常屬於
造型或狀態，而非身份。若“銀灰短髮”既可能是永久特徵，也可能是假髮，先回資產環節
解決，不在提示詞裡擅自定性。

### 場景地理

場景地理用固定入口、主要區塊、視覺軸和錨點之間的關係表達。鏡頭角度變化不會自動
創造新地點。提示詞可以選擇一個視角，但不得為了“好看”搬動門窗。

空間縱深來自可通行路線、遮擋、重疊、尺度參照、光向和空氣層次共同建立。前/中/後景
是可選組織方法，不是每條場景提示詞必須填滿的三欄；單房、平面化視覺方向或需要明確
留白時可以不用。資產場景參考圖預設說明可複用地理，不把劇中盟友、敵人和當前動作提前
擺進去；人物關係、站位與視線由分鏡關鍵幀在準確劇情狀態下擁有。

### 尺度

尺度最好繫結同畫面中的中性參照或明確尺寸關係，而不是隻寫“巨大”或“小巧”。參照物
不可引入劇情角色，也不能與 `empty_stage` 的空場要求衝突；道具可以用帶刻度的底座、
常見手掌尺度或已知功能結構作參照。

### 文字政策

文字有兩層，不得混成一個列舉：

1. **資產來源政策（由資產負責人管理）**：`exact_readable | graphic_only |
   no_readable_text | pending_creator_text`，回答劇情/資產真相是什麼。
2. **本次提示詞的呈現方法（由圖片提示詞環節管理）**：`readable | symbolic |
   blank | postproduction`，回答這次參考圖怎樣處理該真相。

條目必須指向 `視覺設定.md` 的準確資產條目與文字事實，並寫清兩層選擇和對應理由。
預設對映：

| 資產來源政策 | 允許的呈現方法 | 要求 |
|---|---|---|
| `exact_readable` | `readable` 或 `postproduction` | 前者逐字引用；後者保留承載區與精確文字引用 |
| `graphic_only` | `symbolic` | 保留圖形存在/佈局，不新造可辨字義 |
| `no_readable_text` | `blank` 或明確不可讀的 `symbolic` | 不得偶然造成新名字/號碼 |
| `pending_creator_text` | `postproduction` 暫存，或阻斷 `readable` | 不猜文字；保留 `unresolved` 狀態與下游影響 |

需要超出當前對映時，先由資產負責技能按創作者選擇修訂來源政策，再據已接受政策選擇呈現方法；
本階段不能保持原政策卻自行放寬對映。

- `readable`：正文逐字引用已接受文字，並允許清晰可讀；不要同時要求“不要文字”。
- `symbolic`：允許文字感圖形，但明確不要求可辨字義。
- `blank`：承載面保持空白。
- `postproduction`：預留乾淨區域與透視/光照條件，文字後期加入。

文字政策不是對模型效果的保證，而是創作和後期工作的要求。專名、號碼或網址尚未獲得
明確接受時，不要編造。

“語義上必須出現簽名”不等於已經擁有可複製的正式簽名字形。只有簽名歸屬或劇情職責、沒有
創作者確認的字形資產時，保留準確來源說明並阻斷 `readable`；僅在當前文字政策允許
`postproduction` 時可預留承載區，不得用姓名、偽簽名或自行設計的筆畫冒充正式字形。
若人物的接收或反轉依賴這項文字，不得一面保留空白承載區、一面讓人物認出簽名；候選文字
明確寫“正式簽名字形未提供”，並點名受影響的 `IMG-...` / `SHOT-...`；在字形或已確認的後期處理
真正到位前，不寫可讀簽名正文。

### 檢查輸入參考圖（`IMG-08`）

文字政策同時管輸出意圖和輸入參考。只有創作者/參考圖權利人給出可以核對的畫面
說明時把狀態寫為 `creator_described`；執行環境明確授權智慧體檢查輸入參考並完成檢查時，
把狀態寫為 `visually_inspected`。此時才判斷可辨文字、近似字形、號碼、
標牌、螢幕介面、水印和字幕殘留；不能只檢查提示詞正文有沒有寫“無文字”。只有文字
記錄、媒體不可見或未獲授權時保持 `unverified`，不能編造觀察結論。

- `no_readable_text`：若參考仍帶文字風險，先**裁切、清理、遮罩或替換**；會破壞
  身份/地理/構圖時，退回資產或選擇後期處理，不得靠更強的負面詞假裝風險消失。
- `exact_readable`：只允許批准的承載面和逐字內容；舊版本、衝突號碼、其他標牌或
  字幕不能借參考圖進入生成。
- `graphic_only`：允許的只是已接受的圖形職責，不把偶然可辨的偽字當作合格符號。
- 這一步只記錄輸入參考圖的檢查資料與文字風險；本提示詞階段不生成或驗收成片，也不從
  提示詞聲稱文字已經正確渲染。

**`reviewed_invariant`**：依據創作者或參考圖權利人提供的畫面說明，審查者
核對參考圖、文字政策與裁切/清理/遮罩/替換決定是否有來源、是否互相矛盾；沒有
檢查資料時保持 `unresolved`。**“不要文字”之類的負面提示不能清除**參考圖中已有的文字風險。

### 參考圖可以決定哪些內容（`IMG-09`）

每張真實參考圖使用穩定 `REF-...` 槽位；槽位在創作文件裡逐字寫成 `REF-<slot>（順序：<n>）· <專案相對路徑>《<中文名稱>》（用途：<用途>；控制：<範圍>；不得控制：<範圍>）`，並另行說明觀察狀態與未決風險。
調整順序或插入新參考不能改變已有槽位的語義；換圖時在同一槽位明確修訂圖片路徑，不把舊圖的控制邊界靜默轉給新槽位。`IMG-...` 只定位當前《圖片提示詞.md》的提示詞條目。`用途` 是封閉詞表，只能取 `身份`、`造型狀態`、
`地理`、`構圖`、`尺度`、`效果`、`起始幀`、`結束幀`、`風格` 之一；一張圖承擔兩件事就拆成兩個槽位，
不寫「全參考」，也不自造新用途。資產板通常只用到前六個——`起始幀` 和 `結束幀` 屬於鏡頭，不屬於資產板。

- 身份參考不自動決定姿勢、構圖或臨時造型；
- 構圖/尺度參考只借用佔比、機位所在一側、留白或相對尺度，不帶入圖中人物與事件；
- 效果參考只控制已接受目標的形態/範圍，不讓非目標物件一起消失、複製或變形；
- 任一參考都繼續服從文字政策與已確認來源，衝突時退回負責方，不用“全參考”。

這項品質要結合當前專案資料判斷，不能按參考圖數量、用途關鍵詞或固定裁切方式機械判定。

### 負面約束

- **`craft_default`**：負面約束針對可預見失敗，如“不要混入第二套制服”“空場，不出現演員”。
- 不要用“不要模糊、不要肢體錯誤、傑作”等套話覆蓋真正的錨點。
- 排除項不得否定必需項，例如要求舊銅鏽又排除所有磨損，要求 `readable` 又全域性禁字。
- **`reviewed_invariant`**：審查排除項是否會把人物特色、場景功能或道具使用方式一併抹掉。

### 審美語言

“電影感、質感、高階、氛圍感”只有在落實為構圖、材質、色彩關係、光向或景深選擇時才有資訊量。

- **`craft_default`**：每個審美詞儘量落到一個可觀察選擇；刪掉相互替換不改變畫面的近義詞。
- **`craft_default`**：先建立清楚，再新增風格。參考板需要可比較性時，均勻光常優於戲劇光；但這是用途相關預設，不是硬規則。
- **`taste_option`**：寫實度、媒介、顆粒、色調和鏡頭感由視覺風格或創作者決定。
- 禁止用固定詞表或形容詞比例阻斷交付；描述是否空泛，由審查者指出具體缺了什麼。

### 光學與表面描述

**`craft_default`**：對需要明確透視或寫實質感的畫面，寫明機位、取景距離和可見表面特徵。
焦段可輔助表達，但不能據此承諾模型會精確模擬光學。

根據畫面尺度選擇毛孔、布料摺痕或金屬使用痕跡；「乾淨」不必等同於沒有任何紋理和摺痕。
不要給每張圖新增相同的相機引數、瑕疵清單或排除詞。

**`taste_option`**：表面是否平滑、是否修飾，以及寫實程度由已接受的視覺風格決定。
結果用對照圖檢查；畫素紋理指標只作輔助，不能代替人物與材質的視覺判斷。

## 5. 輸出、常見問題與檢查

### 輸出

- 預設在《圖片提示詞.md》寫 `IMG-...` 條目，包含用途、準確視覺設定引用、參考欄位與可複製正文；
- 必要的風險或修訂說明留在正文外，不含媒體檔案或遠端任務資訊。

### 失敗徵兆

- 單看提示詞無法分辨究竟是哪一個身份或版本；
- 錨點被風格套話淹沒；臨時傷勢被寫進永久面貌；
- 空間只有物品清單，沒有方向/關係；尺度靠“很大”；
- “不要文字”與 `readable` 同時存在；負面約束否定了主體；
- 參考圖含有與文字政策衝突的標牌、介面、號碼、水印或字幕，卻只在正文追加“不要文字”；
- 文案含使用者抱怨、內部欄位、生成次數或“根據上圖保持一致”卻無目標引用。

### 檢查

1. **結構**：檢查 ID、版本、型別必需欄位、來源引用、參考圖准入狀態、來源政策到呈現方法
   的對應關係，以及可以直接確定的矛盾。
2. **內容**：審查者引用資產欄位和提示詞句子，判斷身份、場景地理和尺度是否保持，
   不能只說“不夠高階”。
3. **預設**：把泛化詞提前、堆砌或重複視作可改進警告；只在必需事實缺失時才升級。
4. **選擇**：風格和文體差異不單獨阻斷；記錄創作者選擇後，修訂正文時繼續保持。
