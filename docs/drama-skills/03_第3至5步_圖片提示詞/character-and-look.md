# 人物設定圖與 Look Variant

## 身份測試 (`IMG-03`)

人物設定圖須保持同一個已接受身份，並只呈現一套自洽造型。不要把互不相容的服裝、髮型、傷勢、年齡或風化狀態平均成一個合成人。

## 1. 人物設定圖解決什麼

人物設定圖的首要任務是讓後續鏡頭認出“同一個人、此刻這一套狀態”，不混入其他時期的造型或劇情表演。輸入包括已接受的人物身份、一個準確造型、用途、視覺風格、構圖、背景/光線以及來源指標。

**`reviewed_invariant`**：一條 character-sheet 規格必須保持一個身份和一套內在一致的 Look。互斥年齡、髮型、服裝、傷勢、乾溼或清潔狀態不能並存。

## 2. 身份層與 Look 層

### Character 身份錨點

只選跨該專案多個 Look 仍穩定的識別事實：

- 年齡區間與體態（確有識別價值時）；
- 面部輪廓、眉眼/鼻唇的相對特徵，不用審美評分；
- 固定髮質/髮際/自然髮色；若髮型會換則放 Look；
- 不會隨場景消失的痣、胎記、舊傷或身體特徵；
- 與身份繫結、專案確認長期保留的配飾。

不要為了“獨特”新造疤痕、異色瞳、紋身。不要用“網紅臉、完美五官、頂級美女”覆蓋已接受的不對稱或生活痕跡。

### Look 可變狀態

Look 描述一個有效區間內的整體：髮型整理方式、服裝單品與穿法、鞋、妝面、臨時配飾、汙漬/水/血/新傷、服裝損壞。每個 delta 應回答：相對哪個 base，變了什麼，為什麼/從何時生效，保持到哪裡。

- **`craft_default`**：先寫剪裁、層次、領口/袖口、材質與主次色，再寫“職業感”“落魄”等抽象效果。
- **`reviewed_invariant`**：服裝和狀態要能在同一時刻成立。例如“外套完整扣好”和“外套撕開露出內層”需明確區域，否則衝突。
- **`taste_option`**：姿態、表情範圍、檢視數量依參考用途決定，不固定三檢視或固定表情格。

## 3. 構圖方法

### 單圖選擇

1. **身份板**：中性全身或三分之二身為主，清楚顯示比例與一套 Look；可附少量正/側細節，但所有檢視是同一時刻、同一 Look。
2. **面部識別板**：頭肩為主，均勻光，髮際與輪廓完整；適合妝面/身份錨點，不承擔服裝全貌。
3. **服裝 Look 板**：全身正面與必要背面/區域性，突出層次、穿法和鞋；面部仍保持身份，不能換成無臉 mannequin 除非創作者明確只做服裝。
4. **狀態板**：同一 Look 的有因果差異，如雨後溼袖、包紮後的左腕；只展示已接受狀態，不把“前後對比”預設塞進一個畫面。

### 參考友好性

- 身體不要被道具、極端透視或強烈運動遮住關鍵特徵。
- 背景與光線服務識別；預設簡潔、中性、均勻，但視覺風格可覆蓋。
- 表情以用途為準：身份板可平靜或低強度角色態；表演測試可給有限表情範圍，但不要把不同劇情時刻混成同一 pose。
- 配飾說明佩戴位置、相對尺度、材質與是否屬於 Look；手持劇情道具不是預設身份錨點。

### 提示詞寫作順序

```text
人物設定圖用途 + 角色身份錨點
→ 當前單一 Look（從頭到腳、delta 清楚）
→ 構圖/檢視/姿態/表情
→ 材質與主次色、識別友好光線
→ 簡潔背景
→ 保持與排除
```

“23 歲”若來源只寫“二十多歲”，不得假精確。身體描述以可見生產需要為限，避免與劇情無關的物化細節。

## 4. Look/state variant

Variant prompt 不是完整身份重寫。先複用 Character anchors，再突出 delta：

- **基準**：`CHAR-* + LOOK-base` 的精確接受引用；
- **變化**：位置、範圍、材質/顏色變化，例如“右袖肘以下被雨淋深一度，肩部仍幹”；
- **保持**：臉、髮際、體態、未變服裝結構、未受影響區域；
- **連續性**：起因、有效場景/鏡頭範圍及下游繫結。

若只是鏡頭內瞬時表情或姿勢，通常由 storyboard/keyframe 擁有，不新建 Look。若 delta 要改變身份事實，先退回 assets，而不是用 edit prompt 越權。

## 5. 輸出與審查

### 失敗徵兆

- 同時寫制服和便裝、受傷和無傷、幹發和滴水發；
- 不同檢視變臉、換衣或配飾位置漂移；
- 只有“年輕漂亮、電影感、精緻五官”，沒有身份錨點；
- 強戲劇陰影遮住臉部或服裝結構，卻聲稱是識別板；
- 把一次手持物、表情、站姿永久寫入人物身份。

### 證據式檢查

| 問題 | 分類 | 證據 |
|---|---|---|
| exact Character/Look 是否解析 | `structural_invariant` | `視覺設定.md` 的可見 ID 與當前變體 |
| 是否只有一個連貫 Look | `reviewed_invariant` | Look 欄位與 prompt 對應句 |
| 是否保持區別性身份 | `reviewed_invariant` | Character anchors 與畫面描述 |
| 泛化美詞是否擠壓錨點 | `craft_default` | 指出可刪詞與缺失的可見事實 |
| 中性姿態/背景是否適合 | `craft_default` | 用途與構圖的關係 |
| 表情強度、板式數量 | `taste_option` | 創作者/視覺方向 |

最終在 `圖片提示詞.md` 產生一個 `IMG-...` 人物板條目和一段無需回查資產庫也能直接理解的正文；
不產生圖片。

## 6. 製作形態投影與模板槽位

`視覺設定.md` 的專案視覺方向與已明確製作形態決定這張人物板用什麼詞彙畫，不決定畫的是誰。

### 從形態取什麼

| 取用項 | 形態回答的問題 | 落到提示詞的位置 |
|---|---|---|
| 形狀語言 | 輪廓簡化到什麼程度、比例體系是否誇張 | 身份錨點的表達顆粒度 |
| 線條與表面 | 線稿封閉還是散邊、平塗/厚塗/照片式表面 | 材質與主次色段 |
| 材質對光的響應 | 布料、皮膚、金屬在該形態裡怎樣出現明暗與高光 | 識別友好光線段 |
| 層拆 | 身份層、服裝可動層、效果層各自承擔什麼 | 構圖與保持/排除段 |
| 識別通道 | 觀眾主要靠面部結構、剪影、還是線條特徵認人 | 錨點選擇與檢視數量 |

### 形態不得改寫什麼

- Character 身份錨點集合本身：年齡區間、體態、面部結構、永久特徵、長期配飾；
- Look 的已接受組成、cause 與有效範圍；
- 手持道具的歸屬（仍屬 Prop/State）與可讀文字政策；
- 故事狀態：傷勢、溼汙、包紮的因果與生效時間。

形態改變的是**同一錨點走哪條表達通道**，不是錨點集合。若形態以剪影為主要識別通道，就要
為已確認錨點找到剪影能承載的寫法（髮際形狀→髮型剪影缺口、舊傷→輪廓上的缺口、體態→肩背
重心），而不是新增、替換或悄悄刪掉錨點。找不到可靠通道時標為“需創作者決定”，退回
資產或創作者，不擅自換一個更好畫的身份。

### 模板槽位不得覆蓋身份錨點

**`reviewed_invariant`**：模板槽位不得覆蓋已確認的身份錨點；當模板預設值與當前身份衝突時，
**身份優先，模板讓位**。

合成例：角色甲的身份是五十歲上下、體格厚重、肩背略沉。若人物板模板對每個角色機械
追加“九頭身黃金比例、極度修長的雙腿”，這條預設槽位就把角色甲改寫成了另一個人，而且因為它
出現在每張板上，下游會把它當成風格統一而不是錯誤。角色乙即使確實修長，也應由當前
Character 錨點寫出，而不是由模板預設值代寫。

排查方式：把同一批人物板的提示詞並排看，找出**逐字重複且與身份無關**的句子。重複出現的
審美句若不能追溯到某個角色的當前視覺設定，就是模板殘留，刪除或改寫成該角色的真實錨點。

| 檢查 | 分類 | 證據 |
|---|---|---|
| 形態投影是否只落在詞彙層 | `reviewed_invariant` | 形態卡欄位與提示詞對應句 |
| 錨點是否在該形態下真的可見 | `reviewed_invariant` | 識別通道與所選錨點 |
| 模板預設值是否覆蓋身份 | `reviewed_invariant` | 跨角色重複句與當前視覺設定 |
| 未決形態影響哪些必需描述 | 沿用所涉 `IMG` 規則等級 | 只掛起依賴該選擇的識別通道、材質、線條或分層；已確認事實繼續編寫，真實視覺分叉交創作者決定 |
