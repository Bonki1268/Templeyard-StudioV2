# 道具 Plate：尺度、功能、狀態與文字

## 識別測試 (`IMG-05`)

道具板保持尺度、形狀、材質、磨損、功能部件與已接受的文字政策，展示當前狀態，
不得重新設計道具的持久身份。

1. 目的與輸入

## 1. 目的與輸入

道具板讓後續畫面保持同一物體的輪廓、尺度、材料、功能和當前狀態。輸入包括準確的道具身份與狀態、來源指標、用途、尺度參照、視角、功能件、磨損/損壞、主人關聯、文字政策、背景與光線。

道具身份不等於“誰在拿”。換手、開啟、裝入內容、沾水、裂損或貼上標籤通常是 State；永久形制改變才可能需要重新做資產決策。

## 2. 身份與 State

### 持久身份

- 整體輪廓與主要比例；
- 尺寸或與中性參照的比例；
- 主材質、表面工藝和固有色；
- 接縫、扣件、開口、把手、鉸鏈等功能結構；
- 有識別價值的長期磨損或製造特徵。

### 當前 State

- 開/關、摺疊/展開、完整/損壞；
- 當前內容物和是否可見；
- 汙漬、水、燒灼、血、灰塵等有因果的表面變化；
- 所有權/持有關係以及狀態有效範圍；
- 文字內容與承載面狀態。

**`reviewed_invariant`**：提示詞必須能讓形狀、材料、功能彼此成立。例如“透明玻璃密封瓶”不能同時寫成“無開口的實心石塊”。

## 3. 可複用 plate 配方

順序建議：

1. **型別、用途、主體**：道具全貌參考、結構細節或狀態 plate。
2. **尺度與輪廓**：真實尺寸範圍或中性參照，長寬厚關係，主輪廓。
3. **材料與色彩**：主材、次材、反射/粗糙/透明關係。
4. **功能結構**：活動件、開啟方向、握持區域、介面；展示到足以理解功能，不自動演示劇情動作。
5. **道具狀態**：損傷、內容、表面狀態、owner relevance 的可見部分。
6. **檢視與背景**：主體佔比、正/側/必要區域性，乾淨背景與易讀光線。
7. **文字政策**：精確選擇並說明承載面。
8. **保持/排除**：防止變形、錯材、錯狀態或多出複製品。

- **`craft_default`**：若尺度容易誤判，加入不帶身份的參照或給出功能性尺寸關係；不要用劇情角色的手當預設參照。
- **`craft_default`**：對可動部件，選擇一個明確狀態；如確需開/關兩態，分為兩個道具狀態條目。
- **`taste_option`**：產品式懸浮、檯面陳列、正交檢視或環境內靜物由複用目的決定。

## 4. 文字政策

文字是一項資產狀態和製作決策，不是隨手加的裝飾。

不得改寫資產負責技能管理的 `exact_readable | graphic_only | no_readable_text |
pending_creator_text`。本階段只為當前道具板選擇下列呈現方式，並在條目中保留準確資產引用與對映理由。完整對映表見
[common-recipe.md](common-recipe.md)。

### `readable`

逐字使用已接受文字，說明位置、方向、行數/層級和承載面。正文不要改寫或自動糾錯關鍵文書。若需要保密/後期合成，可改為 `postproduction`，不能一邊要求可讀一邊寫“畫面中不要任何文字”。

### `symbolic`

保留標籤/刻痕的視覺存在和佈局，但明確為不可辨識符號，不得偶然形成新名字、號碼或 URL。

### `blank`

指定承載面保持乾淨空白，同時保留其材料、透視和光照。不等於抹掉道具其他結構。

### `postproduction`

預留清楚、無遮擋、透視可跟蹤的區域；描述面積、位置、方向、材質和光線，實際字後期新增。精確文字及來源留在條目說明中，可複製正文只要求預留承載區，不要求生成文字。

**`structural_invariant`**：單個文字承載面不能同時選擇互斥政策；`readable` 與全域性 no-text 衝突時必須先解決。

## 5. 輸出與審查

### 失敗徵兆

- 只說“古老鑰匙、精緻盒子”，沒有比例、形制和材料；
- 開啟/關閉、完好/斷裂、空/裝滿同時存在；
- 可動件不知如何連線，功能靠抽象標籤；
- 文字內容由 prompt 作者臨時編造，或 `readable` 被 no-text 否定；
- 道具主人被畫成 plate 主體，或不同檢視中尺寸/損傷位置漂移。

### 檢查

| 問題 | 分類 |
|---|---|
| 道具身份與狀態、source refs、text policy 可解析且不衝突 | `structural_invariant` |
| 尺度/形狀/材料/功能/current State 足以識別 | `reviewed_invariant` |
| 磨損與狀態是否有因果、沒有汙染永久身份 | `reviewed_invariant` |
| 中性參照、檢視數量、背景方式 | `craft_default` |
| 產品感、寫實度、陳列審美 | `taste_option` |

輸出一個精確繫結的 `IMG-...` 道具板條目和可複製正文；不承諾文字最終生成準確，也不生成媒體。

## 6. 製作形態投影

`視覺設定.md` 的專案視覺方向與已明確製作形態決定這件道具用什麼詞彙被畫出來，不決定它是什麼。

### 從形態取什麼

- **輪廓簡化程度**：該形態允許省略到哪一級仍能與同類物區分；
- **功能件的表達通道**：鉸鏈、開口、握持面、接縫是靠線條、靠材質明暗，還是靠真實結構；
- **材質對光的響應**：金屬、玻璃、木、布在該形態裡怎樣出現反射、透明與粗糙差異；
- **尺度參照的成立方式**：繪製形態常靠對比物與透視線索，實拍形態可用真實景深與已知尺寸；
- **磨損與損壞的通道**：筆觸、色塊邊界、表面紋理還是實拍痕跡。

### 形態不得改寫什麼

- 形制、主要比例與功能結構的連線關係；
- 當前狀態（開合、內容物、損傷、汙染）及其有效範圍；
- 文字政策與承載面；
- 所有權、持有關係以及它們在本圖中的可見依據。

**`craft_default`**：形態越簡化，越要先保住“能區別這一件與同類物”的一兩處結構。Q 版、
水墨或強筆觸形態可以省略次要裝飾，但鑰匙的齒形、藥瓶的封口、箱釦的咬合方式屬於識別通道，
省掉之後 plate 就不再是這件道具的參考。

**`structural_invariant`**：形態不能修改文字政策。若 `readable` 在高度筆觸化或極簡形態下
無法逐字承載，改為 `postproduction` 並寫明理由與預留區域；不得降級為 `symbolic` 而把已接受
文字悄悄丟掉，也不得為了畫面整潔抹去承載面本身。

合成例：角色甲交給角色乙的舊鑰匙，形態選擇為強筆觸繪製。齒形與柄部缺口仍逐項寫出，
柄上刻字按上游政策保持 `graphic_only` → `symbolic`；筆觸隻影響邊緣與表面質感的寫法，
不影響“同一把鑰匙、當前帶有那道缺口”的判定。
