## 建議先整合的五項

1. **連續性鎖 → 角色資料多一個欄位**（`continuity-lock.md`）
   角色和重要道具各寫一條固定短語，例如 `crimson silk temple sash`，系統生成分鏡圖、精緻圖、影片時自動帶進 prompt。只鎖不會隨劇情改變的東西，一集通常只有個位數。

2. **對白估時 → 第 3 步確認條件**（`shot-craft.md`）
   台詞放不進鏡長時，延長或拆鏡，不要讓角色加快語速。每家模型的中文語速要自己實測，專案裡提到的每秒 4.1 字是 MiniMax H3 的數字，不能直接套用。

3. **尾幀插值的代價 → 調整 5b 的設計**（`keyframe-craft.md` 的「尾幀」一節）
   給首尾畫格等於把中間的動作交給模型插值，中間發生什麼不受保證。作者的建議是：如果某個動作是這一格存在的理由，就不要只靠插值，應該拆鏡，或讓那個動作落在首格或末格。這跟你的「中間關鍵畫格（軟性控制）」直接相關：重要的動作轉折，最好拆成獨立分鏡，而不是只當參考圖。

4. **任務中斷恢復 → `comfy-client`**（`adapter-contract.md`、`production_tool.py`）
   拿到 `prompt_id` 就先寫進生成紀錄再開始輪詢。程式中斷後先查未完成的任務並取回結果，確認原任務真的失敗才重新送出。

5. **模型能力檔案 → 補上 Gemini 的寫法**（`target-model-profile.md`）
   專案沒有 Gemini Omni 的專用寫法。這份檔案列了九條會影響提示詞的能力軸（單次時長、參考條件方式、聲音是否同軌生成、正文長度上限等），照著填一份 Gemini Omni 1.1 Flash 的檔案，就能放進 `shot-video.json` 的供應商寫法規則。

## 使用前要注意

- **畫面比例**：原專案以直式 9:16 短劇為主，範例和部分預設要改成你的 16:9。
- **Wan 版本**：專案收錄的是 **Wan 3.0** 的寫法，你的規格書 v3 寫的是 Wan 2.2。要決定改用 3.0，或只參考寫法原則。
- **Seedance 版本**：只收錄 2.0；原專案另有 2.5 的寫法，需要時可以到原專案取。
- **程式檔是參考實作**：`.py` 檔綁定原專案的 Markdown 文件格式（例如簡體檔名 `剧本.md`、`分镜.md`），不能直接接進你的網頁系統，適合拿來看邏輯、改寫成你自己的模組。
- **用語**：自動轉換後仍可能有大陸用語殘留，整合進 prompt 前再順一次。
