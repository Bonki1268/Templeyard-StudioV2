依 `CLAUDE.md` 的規則，一個階段接一個階段開發下去。

最後一個要做的階段 L：$ARGUMENTS（空白就是 13）。

重複以下步驟，**兩個階段之間不要問我要不要繼續**：

1. 讀 `docs/PROGRESS.md`，取得「目前階段」N 與「階段狀態」。
   - 狀態是「停止」：不要繼續做，跳到最後的回報。
   - N 大於 L：跳到最後的回報。
2. 用 **stage-builder** 子代理完成第 N 階段（傳入階段編號 N）。
3. stage-builder 回報「停止」：跳到最後的回報。
4. stage-builder 回報「完成」：用 **test-auditor** 子代理稽核第 N 階段。
5. 把稽核結果附在 `docs/progress/stage-NN.md` 最後的「稽核」一節。
   - **通過**：PROGRESS 的「目前階段」改為 N+1、「階段狀態」改為「未開始」、「測試提交」清空，階段一覽表標示完成；commit `docs(第N階段): 稽核通過`。只輸出一行進度，例如「第 3 階段完成：12 個場景、48 個單元測試」，然後回到第 1 步。
   - **不通過**：「階段狀態」改為「停止」，稽核發現的問題寫進「等你處理」；commit `docs(第N階段): 稽核未通過`，跳到最後的回報。

最後的回報（繁體中文，30 行以內）：

- 這次完成了哪些階段，各自的情境數與測試數
- 停在哪個階段、為什麼
- 「等你處理」的完整清單，標出哪些會擋住下一個階段
- 下一步該怎麼做
