description: 用 BDD＋TDD 做下一個開發階段，做完停下來回報
argument-hint: [給這個階段的額外指示（可省略）]
---

依 `CLAUDE.md` 的規則，完成**一個**開發階段，然後停下來回報。

1. 讀 `docs/PROGRESS.md`，取得「目前階段」N 與「階段狀態」。
   - 狀態是「停止」：不要繼續做；先讀「等你處理」，問我要怎麼處理，然後結束。
   - N 大於 14：檢查 PROGRESS「階段一覽」；還有未完成的階段（例如第 13 階段等實測）就列出來並回報，否則回報全部階段都已完成；然後結束。
2. 用 **stage-builder** 子代理完成第 N 階段。傳給它：階段編號 N；如果有額外指示就一起傳：$ARGUMENTS
3. stage-builder 回報「停止」：直接把原因與「等你處理」回報給我，然後結束。
4. stage-builder 回報「完成」：用 **test-auditor** 子代理稽核第 N 階段。
5. 把稽核結果附在 `docs/progress/stage-NN.md` 最後的「稽核」一節。
   - **通過**：PROGRESS 的「目前階段」改為 N+1、「階段狀態」改為「未開始」、「測試提交」清空，階段一覽表標示完成；commit `docs(第N階段): 稽核通過`。
   - **不通過**：「階段狀態」改為「停止」，把稽核發現的問題寫進「等你處理」；commit `docs(第N階段): 稽核未通過`。
6. 用繁體中文回報（20 行以內）：
   - 做了什麼，對應哪些 F
   - 情境數、單元測試數、稽核結果
   - 等你處理的事項
   - 下一步：通過就打 `/next-stage` 或 `/auto-dev`，不通過就說明需要我決定什麼
